## 三个可以直接讲的结论

### 1. 训练有效,但只改善了「怎么做事」,没碰「做得对不对」

经过配对检验、噪声地板对照、排除基础设施故障后**仍然成立**的只有两条:

| 维度 | 变化 | p |
| --- | --- | ---: |
| **输出格式合规**(白烧轮次) | 13.4% → **1.9%** | 2e-08 |
| **可维护性**(判官票数,8B) | 53 → **92** | **0.0050** |
| **可维护性**(14B) | 95 → **151** | **0.0006** |
| **可维护性**(RL:SFT→RFT-2) | 54 → **106** | **0.0001** |

而 correctness **每一个子维度都没动**:通过率 p=0.90、编译 p=0.85、逻辑 p=0.50。

> **训练把模型的「手」训好了,缺的是「眼睛」** ——
> 它能干净利落地执行,但没有任何机制告诉它做得对不对。

### 2. 下一步最该做的:给 RL reward 加「补丁能否编译」

**42% 的失败只是代码编译不过**(C/C++ 94%、PHP 68%,而 Go/Python/Java 是 0%)。

排除编译不过的题后,通过率从 9–19% 跳到 **22–42%,翻 2 倍以上**。

| 干预 | 收益 |
| --- | ---: |
| 提高输出预算 4096→8192 | **0** |
| deadline 强制交卷 | +135 题(通过率 0.7%) |
| 原生多轮训练 | 0–7% |
| **让代码能编译** | **通过数翻 2 倍** |

**编译检查是秒级的、不需要 oracle 和测试环境**,却覆盖 42% 的失败 ——
**比试过的所有干预高一个量级。**

### 3. 判官面板有设计缺陷,而且修复不花钱

| 判官 | 独自否决 | 移除后排名变化 | 判自己 vs 判同门 |
| --- | ---: | ---: | --- |
| **claude-opus-5**(榜首) | 627 | **9/14** | **13.5% vs 27.3%** |
| gpt-5.6-sol | 138 | 2/14 | 6.3% vs 6.7%(正常) |
| **gemini-3.6-flash** | **4** | **0/14** | — |

- **gemini 是橡皮图章**:占三分之一判分预算,买到 **0 个排名变化**;
- **opus-5 对自己的否决率是对同门的一半** —— 同门没得到优待,
  所以是自我偏袒而非风格相似。按同门标准重算,
  它的 Maint 从 160 → 134,**从第 1 掉到第 3**。

**修复方案:用替补判官顶替 gemini 的槽位** —— 槽位不花钱。

> **替补已实测验证可行**:`deepseek-v3.2` 判了 370 道题,
> 在 opus-5 和 sol 都通过的 161 题上**独自否决 20 次**(gemini 只有 1 次)。
> **它会独立地不同意 —— 这正是合议需要的。**

> 其余 11 个模型都不是判官,**相对次序不受影响**。

## 如果被问到「怎么保证结论可靠」

本周**六次报错并撤回**,形态高度集中:

| 次数 | 错误 | 判据 |
| ---: | --- | --- |
| 1–2 | 比较边际计数、单次跑下结论 | **配对检验 + 重复采样** |
| 3–4 | 二值阈值毁掉信号(p 从 0.21 → 1e-6);主榜排名也被它扭曲 | **迭代决策用连续量** |
| 5–6 | 「边际百分比看着像趋势」 | **配对检验之前都不算数** |

另有三次**同一形态**的字段误读(多值字段当布尔量)。
第三次之后没有再修那一处,而是 **grep 全部脚本** ——
命中 7 处,其中 2 处在关键路径上。

> **判据:同一个错误犯第三次时,它已经不是 bug,是习惯 —— 去 grep 全部。**
