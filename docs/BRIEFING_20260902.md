## 三个可以直接讲的结论

### 1. 训练有效,但只改善了「怎么做事」,没碰「做得对不对」

经过配对检验、噪声地板对照、排除基础设施故障后**仍然成立**的只有两条:

| 维度 | 变化 | p |
| --- | --- | ---: |
| **输出格式合规**(白烧轮次) | 13.4% → **1.9%** | 2e-08 |
| **可维护性**(判官票数,8B) | 53 → **92** | **0.0050** |
| **可维护性**(14B) | 95 → **151** | **0.0006** |
| **可维护性**(RL:SFT→RFT-2) | 54 → **106** | **0.0001** |

而 correctness **每一个子维度都没动**:通过率 p=0.90、编译 p=0.85、逻辑 p=0.50。

> **训练把模型的「手」训好了,缺的是「眼睛」** ——
> 它能干净利落地执行,但没有任何机制告诉它做得对不对。

### 2. 下一步最该做的:给 RL reward 加「补丁能否编译」

**42% 的失败只是代码编译不过**(C/C++ 94%、PHP 68%,而 Go/Python/Java 是 0%)。

排除编译不过的题后,通过率从 9–19% 跳到 **22–42%,翻 2 倍以上**。

| 干预 | 收益 |
| --- | ---: |
| 提高输出预算 4096→8192 | **0** |
| deadline 强制交卷 | +135 题(通过率 0.7%) |
| 原生多轮训练 | 0–7% |
| **让代码能编译** | **通过数翻 2 倍** |

**编译检查是秒级的、不需要 oracle 和测试环境**,却覆盖 42% 的失败 ——
**比试过的所有干预高一个量级。**

### 3. 判官面板有一个真缺陷 —— 以及一个我误报的缺陷

| 判官 | 独自否决 | 移除后排名变化 | 占判分预算 |
| --- | ---: | ---: | ---: |
| claude-opus-5 | 627 | 9/14 | 1/3 |
| gpt-5.6-sol | 138 | 2/14 | 1/3 |
| **gemini-3.6-flash** | **4** | **0/14** | **1/3** |

**真缺陷:gemini 是橡皮图章。**
它花掉三分之一的判分预算,买到 **0 个排名变化**;
在另外两人都通过的题上,它总共只独自否决过 **4 次**。

**修复方案已实测验证**:`deepseek-v3.2` 判了 370 题,
在 opus-5 和 sol 都通过的 161 题上**独自否决 20 次**(gemini 只有 1 次)。
**它会独立地不同意 —— 这正是合议需要的,而且槽位是现成的,不花钱。**

⚠️ **我昨天报的「榜首在给自己打分」,今天撤回。**

当时的依据是 opus-5 否决自己 13.5%、否决同门 27.3%,正好一半,
据此推算它的 Maint 会从 160 掉到 134、从第 1 掉到第 3。

**那是推算,不是测量,而且对照组选错了。**
今天我引入一个没有利害关系的判官做共同参照,直接测:

| 被判模型 | opus-5 判 | 中立判官判 | 宽松度 Δ |
| --- | ---: | ---: | ---: |
| claude-opus-5(自己) | 50.3% | 63.0% | −12.7pp |
| claude-opus-4.8(同门) | 31.4% | 45.2% | −13.8pp |
| gpt-5.6-terra(无关) | 34.7% | 51.8% | −17.1pp |

**自我偏袒 = +2.8pp,p = 0.44,95% 置信区间 [−3.7, +9.2] 排除了 13.8pp。**
标准误 3.3pp —— 真有我说的那么大,这个检验有 >99.9% 把握测到。
**不是样本不够,是效应不存在。**

错在哪:**同门对照控制了「风格相似」,没控制「质量差异」。**
opus-5 的补丁本来就更好 —— 中立判官给它 63.0%、给 opus-4.8 45.2%。
它否决自己少,主要是因为自己的补丁好。

**榜首不动。**
