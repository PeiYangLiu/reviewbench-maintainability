## 三个可以直接讲的结论

### 1. 训练有效,但只改善了「怎么做事」,没碰「做得对不对」

经过配对检验、噪声地板对照、排除基础设施故障后**仍然成立**的只有两条:

| 维度 | 变化 | p |
| --- | --- | ---: |
| **输出格式合规**(白烧轮次) | 13.4% → **1.9%** | 2e-08 |
| **可维护性**(判官票数,8B) | 53 → **92** | **0.0050** |
| **可维护性**(14B) | 95 → **151** | **0.0006** |
| **可维护性**(RL:SFT→RFT-2) | 54 → **106** | **0.0001** |

而 correctness **每一个子维度都没动**:通过率 p=0.90、编译 p=0.85、逻辑 p=0.50。

> **训练把模型的「手」训好了,缺的是「眼睛」** ——
> 它能干净利落地执行,但没有任何机制告诉它做得对不对。

### 2. 下一步最该做的:给 RL reward 加「补丁能否编译」

**42% 的失败只是代码编译不过**(C/C++ 94%、PHP 68%,而 Go/Python/Java 是 0%)。

排除编译不过的题后,通过率从 9–19% 跳到 **22–42%,翻 2 倍以上**。

| 干预 | 收益 |
| --- | ---: |
| 提高输出预算 4096→8192 | **0** |
| deadline 强制交卷 | +135 题(通过率 0.7%) |
| 原生多轮训练 | 0–7% |
| **让代码能编译** | **通过数翻 2 倍** |

**编译检查是秒级的、不需要 oracle 和测试环境**,却覆盖 42% 的失败 ——
**比试过的所有干预高一个量级。**

### 3. 判官面板:两个判官都把自己排第一,而第一名本身分辨不出来

让四个判官各自单独给 14 个模型排一次名(同一批 402 题、同一份产出):

| 判官 | 它心中的第 1 名 |
| --- | --- |
| claude-opus-5 | **claude-opus-5(自己)** |
| gpt-5.6-sol | **gpt-5.6-sol(自己)** |
| gemini-3.6-flash | gpt-5.6-sol |
| **deepseek-v3.2(中立,不在被评测集合)** | claude-opus-5 |

**两个坐在判官席上的被评测模型,都把自己排在第一。2/2。**

而中立判官眼里,**第一名是平局**:

```
claude-opus-5 233   vs   gpt-5.6-sol 228
配对检验:opus-5 独赢 73 题,sol 独赢 68 题,p = 0.74
```

**现榜把两者拉开到 160 vs 149,那个差距是由包含它们自己的面板造出来的。**

> **结论:第 1 名这个位置,本 benchmark 目前分辨不出来。**
> 第 4 名往后不受影响 —— 那些模型都不是判官,相对次序稳定。

**另一个独立的缺陷:gemini 是橡皮图章。**
在另外两人都通过的题上它总共只独自否决过 **4 次**,
移除它 14 个模型排名一个都没变,而它占三分之一判分预算。

**下一版要做的**:判官席上不放被评测模型。
`deepseek-v3.2` 会独立提反对意见(独自否决 20 次 vs gemini 1 次),
**但它分不清模型强弱**(否决率与榜单分相关 r=−0.50,opus-5 是 −0.85),
所以它能补位、不能单独定榜。

---

⚠️ **这一节我改过两次,前两版都是错的,过程本身值得讲。**

| 版本 | 说法 | 错在哪 |
| --- | --- | --- |
| 第一版 | opus-5 自我偏袒,会从第 1 掉到第 3 | 用同门当对照,**控制了风格没控制质量** |
| 第二版 | 自我偏袒测不出,第 1 名稳固 | 用了原始通过率,**而全票规则下它不决定榜单** |
| **现在** | **两个判官都选自己,第 1 名是平局** | 换成不需要争议尺子的问法 |

**教训:当一个量的答案随着尺子来回变,不要继续换尺子 ——
换一个不需要那把尺的问法。**
「自我偏袒有多少 pp」需要一个公认的中立参照,而我没有;
「每个判官心里的第一名是谁」不需要参照,数据直接给答案。
