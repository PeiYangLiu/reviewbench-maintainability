## 一、本周结论(三句话)

1. **主榜完成,但发现判官面板有设计缺陷**:14 个模型跑完四门,Opus 5 以 120/402 居首。**但 Opus 5 本身是三个判官之一,且对自己的否决率是对同门的一半(13.5% vs 26.9%)** —— 按同门标准重算会从第 1 掉到第 3。另外三判官里 gemini 独自否决仅 4 题(opus-5 是 627),**合议实际上退化成了两人**。其余 11 个模型不是判官,相对次序不受影响。
2. **训练侧有效,但代价是产量**:补丁质量提升 44–84%(p 最小 3e-11,三次重复确认),同时产量下降 11–17 题。**关键前提是换用连续指标——用"三判官全票"这个二值口径完全测不出来。**
3. **找到一个量级级别的可行动瓶颈:42% 的失败只是代码编译不过。**失败的 66% 是「改坏了原本通过的测试」,但其中 **99.3% 是全部测试都挂** —— 那不是逻辑错,是 g++ / PHP 的编译错误。按语言分层极干净:**C/C++ 94.2%、PHP 68.1% 是语法错,Go/Python/Java 是 0%**。验证:排除编译不过的题后,**通过率从 9–19% 跳到 22–42%(翻 2 倍以上)**。**编译检查是秒级的、不需要 oracle 和测试环境**,却能覆盖 42% 的失败 —— 这比本项目试过的所有干预(预算翻倍 0、deadline 0.7%、原生多轮 0–7%)高一个量级。

## 五、六次撤回(方法论)

本周有六次报错并撤回。前两次是统计方法问题:

| 错误做法 | 后果 | 正确做法 |
|---|---|---|
| 比较**边际计数** | 把真效应报成"测不出差异" | 配对方向检验,输出 `(只A, 只B, p)` |
| 用**单次跑**下结论 | 先把 8B 的退化报成"持平",又把运气报成"质量显著提升" | 组内极差:产量门 11–38 题、**质量门可达 8 题**(不是我先前估的 3.3)。小于它必须重复 |

**第三个也是最贵的一个:指标本身把信号毁了。** "三判官全票"这个二值阈值
丢掉了所有"差一票"的题——14B 上有 4 道计分题,旁边趴着 15 道边界题。
重复采样时边界题随机翻转,分数就在 1 到 9 之间跳。换成连续量(总票数)后,
变异系数降低 23 倍,同一批数据的结论从 p=0.21 变成 p=1e-6。
**发布口径可以用全票,但迭代决策必须用连续量。**

**而且这个阈值不只影响训练评测——它也扭曲了主榜排名。**把同样的处理
应用到已发布的 14 个模型上,**9 个的次序变了**:opus-5 从第 1 掉到第 3,
gpt-5.6-sol 从第 2 升到第 1,Qwen3.6-27B 从第 9 升到第 7。
原因是全票口径丢掉「2 票通过」的题,而**弱模型丢掉的比例高得多**
——gpt-oss-120b 每 1 道全票题背后有 2.8 道差一票的题。
所以全票不是「更严格的同一把尺」,而是**额外给「判官意见一致」加分的另一把尺**。

发布口径**不改**(全票有明确语义,且头部 5 名的集合在两种口径下相同),
但榜单已补上加权票数与「边界比」两列并说明如何解读。
详见 `PITFALLS.md` P104/P105。

**第四次撤回,这次错的是「建议」而不是「结论」。** 我基于第 6.1 节的
失败模式分析,给 SFT 提了「保留 teacher 跑测试的轮次」。
发出去之后才去看工具列表——**harness 里根本没有跑测试这个能力**
(只有 `read/find/edit/finish`),teacher 的 3,626 条轨迹里也一次都没有。
建议已撤回。**教训:一条听起来完全合理的建议,只要没人看一眼工具列表,
就能一路传下去变成训练计划;而证伪它只需要一次 grep。**

**第五、六次撤回,都是同一个形态:边际百分比看着像趋势。**
- 「训练加剧了 finish 死循环」(1.5%→2.2%→5.0%)—— 单变量配对 p=0.58/0.75,**撤回**;
- 「scope 违规训练后减半」(7.6%→4.7%)—— 单变量配对 p=1.00/0.12,**撤回**。

两次唯一显著的对比都**同时改了训练和服务格式**,归因不到训练。
**而 P99 早就写过「数字小的时候最容易退回边际比较」——
我写了那条,又在同一个晚上违反了它两次。**

> **判据:任何用「A 是 x%,B 是 y%」表述的改进,配对检验之前都不算数。**
> 尤其当两者都是个位数百分比时 —— 分子只有二三十题,边际差异极易是噪声。

**"提高输出预算"也是一个反面案例**:它确实让产量涨了 19–24 题,但那些新增补丁的四门通过率只有 0–4%,**最终分一分没涨**,截断最严重的模型反而掉了 8 分。

> **规律(三次独立验证)**:产量侧干预会把"没交卷"变成"交了张不对的卷",不会把"不会做"变成"会做"。deadline 强制交卷 +135 题(通过率 0–0.7%)、预算翻倍 +19/+24(0–4%)、原生多轮 +14/+8(0–7%)。

## 六、下一步建议

1. **上 Qwen3.6-27B 做训练**。它是唯一 maintainability 有真实刻度的开源尺寸(85/402),8B/14B 的绝对值太低,改善难以观测。
2. **按判官结果筛训练数据后重训**。过滤表已交付,建议按 `majority` 保留 78%。这是不改算法、不换基座的最便宜改进。
3. **在训练中引入可执行反馈**。这是本周最可行动的一条,理由见下。

### 6.1 拆开 correctness 之后:2/3 的失败是「把能跑的代码改坏了」

「correctness 是瓶颈」原本只是个笼统说法。拆成失败模式后:

| 失败原因 | 占全部失败 |
| --- | ---: |
| **补丁把原本通过的测试改挂了** | **66–72%** |
| 补丁打不上 | 1–7% |
| 根本没交卷 | 0.3–5% |

其中约 60 个百分点有**基线对照证实**——同一套测试在打补丁前跑是过的,
打完就挂了。**既不是题难,也不是环境坏,是补丁真的破坏了行为。**

两个推论:

- **产量早就不是瓶颈**(没交卷+打不上 < 10%)。这从另一个方向印证了
  「产量侧干预不涨分」。
- **训练完全没有改变这个比例**:base 65.7% → 训练后 66.9%/72.1%,
  **一点没动**。SFT/RL 教会了模型「怎么做事」,
  **但两边的训练信号里都没有任何一项和「有没有破坏已有行为」相关。**

**而且模型根本没有验证的能力。**harness 的工具只有
`read / find / edit / finish` 四个,**没有 bash、没有测试执行**;
teacher 的 3,626 条轨迹里也一次测试都没跑过(它同样没这个能力)。
所以这不是「模型不小心」,是**结构上不可能验证**。

于是可选项只有两个:

1. **RL reward 加一项「补丁能否编译」** —— **这是性价比最高的一条**。
   秒级、不需要 oracle、不需要测试环境,却能拦住 C/C++ 94% 的失败(见 6.1)。
2. **RL reward 加一项 P2P(pass-to-pass)通过与否** ——
   同样是二值自动判定,但需要完整测试环境,成本高一个量级。
3. harness 增加测试工具 —— 可行,但属于协议改造,成本最大。

### 6.1 42% 的失败只是编译不过 —— 按语言分层

| lane | 语法/编译错 | 逻辑错 | 语法占比 |
| --- | ---: | ---: | ---: |
| **native (C/C++)** | **425** | 26 | **94.2%** |
| **scripted (PHP)** | **207** | 97 | **68.1%** |
| gopy (Go/Python) | 0 | 423 | **0.0%** |
| jvm (Java) | 0 | 332 | **0.0%** |

**验证**(只看有编译门槛的 lane,118 题):

| arm | 整体通过率 | **排除构建坏后** |
| --- | ---: | ---: |
| base-qwen3-8b | 14.4% | **32.7%** |
| native-qwen3-14b | 17.8% | **36.2%** |
| r16-nobanner-14b | 18.6% | **42.3%** |

**翻 2–2.4 倍。**(外推假设构建坏的题若能编译则通过率相同,可能偏乐观;
即便打对折,仍大于本项目试过的所有其他干预。)

**压力测试过了**:我怀疑过这些编译错误是 harness 的单文件约束造成的
(native lane 全部 520 题的参考答案都不是单文件改动,97% 同改 .h/.cc)。
**验证推翻了这个怀疑** —— 未声明错误率与能力强负相关:
gpt-5.5 通过 61/65、错误率 1.5%,而 Devstral 是 21/65、35.4%。
**强模型在同样约束下几乎不犯,所以编译错误测的是真实能力。**

**额外收获:native lane 是区分度最高的 lane**(94% vs 42%),
失败原因还能机械区分(编译 vs 逻辑)。**若要高信噪比的评测子集,选它。**

**这个瓶颈藏在两层聚合底下**:
「correctness 18%」→「66% 改坏了测试」→「其中 42% 是编译不过」→
「C/C++ 94%、Go/Python 0%」。**每往下一层只需一次 groupby,
可行动性提高一个量级。**

### 6.2 附带结论:学到的行为极度依赖服务格式(8 倍)

`native-*` / `nobanner-native-*` / `r16-nobanner-*` **是同一份权重**,
只改评测时的服务格式。平均每题读取(`read+find`)次数:

| 权重 | 带 banner@32 | 裸 JSON@32 | 裸 JSON@16 |
| --- | ---: | ---: | ---: |
| Qwen3-8B 第二版训练 | **3.26** | 0.40 | 0.46 |
| Qwen3-14B 第二版训练 | **3.21** | 1.21 | 0.83 |

402 题配对检验:8B p=2.9e-08,14B p=2.2e-04。

**只是去掉 `<tool_response>` 包裹,8B 的读取行为就掉 8 倍**,
退回基座水平(基座 = 0.08)。

**但这是行为差,不是分数差。**分数侧跑下来:8B 的 8 倍行为差
换来 **p=0.83**(一分没差);14B 单次跑显著(maint 155 vs 108,p=0.0075),
但 `nobanner` 臂没有重复跑,按第五节的教训**不能当已确认**。

结论:**对齐训练/推理格式是正确工程(行为差实打实),
但不要拿它预期分数提升 —— 那还没有证据。**

### 6.3 SFT 到底做成了什么

| | read+find | edit |
| --- | ---: | ---: |
| **teacher** | **4.82** | 1.45 |
| 基座 Qwen3-8B | 0.08 | 4.02 |
| **第二版训练 8B** | **3.26** | **1.77** |

基座是「几乎不读、猛改」,teacher 是「多读、少改」。
**训练把 8B 的形态拉到了几乎和 teacher 一致**,但 correctness 没跟着涨。
**学到的是 teacher 的动作分布,不是 teacher 的判断力(读哪里、改什么)。**

### 6.4 一个没报告过的训练成果:白烧轮次降 96%

「白烧轮次」= 这一轮模型没产出任何可执行动作(API 报错 或 输出非合法 JSON)。

| arm | 总轮次 | 白烧 | 占比 |
| --- | ---: | ---: | ---: |
| 基座 Qwen3-8B | 2422 | **325** | **13.4%** |
| 基座 Qwen3-14B | 2646 | **384** | **14.5%** |
| **第二版训练 8B** | 2535 | 49 | **1.9%** |
| **第二版训练 14B** | 2448 | 53 | **2.2%** |

配对检验(同题、单变量):**8B p=2.25e-08、14B p=1.97e-06。**

拆开是两类,训练把两类都消灭了:基座 8B 的 **121 次撑爆上下文 → 0**,
**203 次 JSON 格式错 → 13**。基座的典型失败是无休止自我辩论直到超长,
永远输出不到那个 JSON。

**为什么这把尺重要**:它不经过 correctness、不经过判官,
纯机械判定、方差极小。四门分数要过两道有损环节(P104 的边界比 250–550%),
**要判断「训练有没有学到东西」,白烧率比 Final 灵敏得多。**
已固化为 `scripts/summarize_wasted_rounds.py`。

**但它没有转化成分数**(correctness p=0.90)。省下的 276 轮,
模型拿去做的还是同样做不对的事 —— 又一次印证「产量侧干预不涨分」。

### 6.5 所有训练结论重跑了一遍配对检验:能站住的只有两条

因为今晚撤回了两次,我把**每一条**都用同一把尺重跑
(383 题、同协议 v2-tool-response、单变量配对):

| 维度 | 方向 | p(8B / 14B) |
| --- | --- | --- |
| **白烧轮次** | ✅ **−96%** | **2e-08** |
| **可维护性票数** | ✅ **+59~74%** | **0.005 / 0.0006** |
| **没交卷** | ❌ **变差 +15 题** | **0.0015** / 1.00 |
| correctness 通过 | ⬜ 无变化 | 0.90 / 0.26 |
| 编译不过 | ⬜ 无变化 | 0.85 / 0.68 |
| 逻辑改坏 | ⬜ 无变化 | 0.50 / 1.00 |

**结论比此前精确:不是「correctness 没改善」,而是
correctness 的每一个子维度都没改善** —— 编译、逻辑、通过率全部纹丝不动。
而改善的两项**都是「形式」层面的**(输出格式、判官认可的风格)。

还查出一条此前没注意的负面效应:**8B 训练后「没交卷」多了 15 题**。
结合 finish 死循环看:训练后的模型更倾向「决定结束」,
而当它错误地决定结束时,就什么都交不出来。

> **方法论:一次性把所有结论用同一把尺重跑,比逐条等着被推翻便宜得多。**
> 这次不到十分钟,同时确认了两条真结论、三条「无变化」是真的没变,
> 还发现了一条完全没注意的负面效应。

### 6.6 RL 侧的证据比 SFT 侧硬:它有噪声地板

RL 的三个 noise 臂是**同一个 adapter 跑三遍**,提供了「重跑一次的抖动」这把尺:

```
噪声地板      rep1 vs rep2  票数 60 -> 61   p=0.8957
             rep1 vs rep3  票数 62 -> 55   p=0.3961
             rep2 vs rep3  票数 57 -> 58   p=1.0000

RFT 效应      SFT -> RFT-1  票数 56 ->  84  p=0.0263
             SFT -> RFT-2  票数 54 -> 106  p=0.0001
```

**噪声臂之间最大差 7 票,RFT-2 相对起点差 52 票 —— 是噪声的 7 倍。**

同样是 p<0.05:**有地板时你知道效应是噪声的 7 倍;
没有时你只知道「不太可能是巧合」。** SFT 侧现在就卡在后者。

**建议:SFT 侧补三个同配置重复臂。**这是三倍算力,
但 RL 侧证明这笔钱买到的是「结论能不能拿去做决策」。

(诚实的限制:`RFT-1 → RFT-2` 是 p=0.0586,**第二轮的增量尚未确认**。)

### 6.7 三个缺口同源:teacher 从不犯错,所以没有负例

本周查出的三处问题指向同一个成因:

| 现象 | teacher 数据里缺的负例 |
| --- | --- |
| 动作形态已逼近 teacher,correctness 不涨 | — |
| **66–72% 的失败是改坏了原本通过的测试**,训练前后不变 | teacher 不改坏,没有「改坏了怎么修」 |
| **4–5% 的题卡在「finish 被拒 → 再 finish」死循环**,全部 0 分 | teacher 不空调 finish,没有「被拒了怎么恢复」 |

第三条是本周新查出的 bug。实测 teacher 的 3,626 条轨迹里
**finish 被拒 0 次**(它基本不会在 edit 之前调 finish),
所以模型见过的每一条 finish 都是成功的 ——
真被拒时它唯一会做的就是**再调一次**,直到 16 轮烧光。

**这比「数据量不够」更具体,也更好补:**
窄模式的脱困样本可能**几十条就够**,不需要大规模数据。
建议按性价比:①构造少量脱困样本 ②RL reward 对「重复无效动作」扣分
③引入执行反馈(最贵但最对)。
