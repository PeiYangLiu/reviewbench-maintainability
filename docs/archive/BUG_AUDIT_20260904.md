## EVAL-01：票数被当成布尔值，改变了 FINAL 门槛

**位置：** `scripts/compare_arms_paired.py:195`。

`--metric votes` 下，`maint[arm][t]` 是 0 至 3 的整数；
`maint[arm][t] and corr[arm][t]` 因而把 1/3、2/3 票也算作 FINAL 通过。
它不是发布口径的“全票可维护性通过且 correctness 通过”。

仅修正这一阈值、保持原脚本使用的配对样本交集，得到：

| 对比 | 原 FINAL 计数 | 原 p | 全票 FINAL 计数 | 全票 p |
|---|---:|---:|---:|---:|
| base 8B / native 8B | 20 / 12 | 0.1338 | 0 / 3 | 0.2500 |
| base 14B / native 14B | 25 / 25 | 1.0000 | 1 / 6 | 0.0625 |
| RL-SFT / RFT1 | 9 / 14 | 0.3593 | 0 / 1 | 1.0000 |
| RL-SFT / RFT2 | 7 / 16 | 0.0490 | 0 / 4 | 0.1250 |

这里尚未同时修复 EVAL-02，不能把此表当作新的完整 402 题发布榜。
影响的是下列报告的配对比较 FINAL 行，不是说其中所有统计都使用了错误阈值：

- [SFT 八臂报告](SFT_EIGHT_ARM_FOUR_GATE_402.md)第二节。
- [RL 六臂报告](RL_SIX_ARM_FOUR_GATE_402.md)第二节。

**修复方向：** 连续票数与发布门保持两个独立变量；FINAL 始终使用明确的
全票条件，不能随 `--metric` 改变。回归案例应覆盖 correctness 通过且
票数分别为 0、1、2、3 的情况。

## EVAL-02：模型没有交补丁，被误当成“没有测量”

**位置：** `scripts/compare_arms_paired.py:57–59`；
`scripts/summarize_four_gate.py:40–44`。

`generation_failed` 记录没有 panel verdict，被 `if not panel_votes: continue`
丢弃。随后配对比较只取两臂有 verdict 的交集：一臂没有补丁时，另一臂同题的
结果也消失。模型失败应记零，与真正的判官拒绝、基础设施缺失不同。

将已知生成失败补为零、继续排除真正缺失的判官结果，重算连续票数：

| 对比 | 原配对题数 | 补零后题数 | 原票数 | 补零后票数 | 补零后 p |
|---|---:|---:|---:|---:|---:|
| base 8B / native 8B | 358 | 399 | 53 / 92 | 56 / 94 | 0.008781 |
| base 14B / native 14B | 357 | 399 | 95 / 151 | 100 / 156 | 0.001269 |
| RL-SFT / RFT2 | 350 | 399 | 54 / 106 | 56 / 111 | 0.0000253 |

例如 base 8B、native 8B 分别有 17、27 道无补丁任务，不能从分母中删除。
399 而非 402，是因为这些比较仍排除了 3 道真正缺少判官结果的题。
本项修正没有消除上表中的可维护性票数提升，但改变了其比较范围和精确统计。

**修复方向：** 从固定任务集合建立状态表，区分已知模型失败、已知成功和未完成
测量。已知无补丁任务的可维护性及 FINAL 为零；缺失判官、缺失 correctness
和基础设施失败保留明确的缺失原因，不能统一当零或统一丢弃。

## INFER-01：没有隔离思考区与最终动作

**位置：** `scripts/generate_agentic_patches.py:637–671,1613`。

`parse_action()` 对整个回复提取 JSON，包括 `<think>` 中的候选动作；
`prefer_edit` 还可能在最终动作是 finish 时选择此前的 edit。
思考正文中的引号也会影响整个回复的 JSON 扫描状态。

现有 AutoPas 样本的第 2 轮已实际发生：

| 内容 | 动作 |
|---|---|
| 最终 JSON | 修改第 78 行，内容为 `std::unique_ptr<TraversalInterface<InteractionTypeOption::pairwise>>` |
| 实际执行 | 修改第 94 行，内容为 `std::unique_ptr<TraversalInterface<InteractionTypeOption::threeBody>>` |

实际执行的 JSON 存在于思考区，且该轮没有执行错误。证据为
`generation-20260831-native/base-qwen3-8b/generation/Qwen_Qwen3-8B/generation_results.jsonl:4`，
任务 ID 为
`github__AutoPas__AutoPas__pull_751__comment_1400534164__dead_code`。
不能把这个案例扩大成“所有模型、所有轨迹都受到影响”。

**修复方向：** 只从最终回答区解析动作；保留完整原始回复用于历史和审计，
但不执行思考区候选。思考未闭合或没有完整最终动作时记录明确的失败；
覆盖“思考区 edit + 最终 finish”和“思考区、最终区有不同 edit”的回归案例。
